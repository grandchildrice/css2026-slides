### 本研究との差分
SPECA系は「仕様文書 → プロパティ → 監査」。speca-lean4-plugin は「Lean定理 → プロパティ」経路を実装済み。**本研究はその一次情報供給元である証明の前提が、仕様文書だけではどれだけ拾えないかを検証した予備調査**。グラント成果群の中では「供給元側の検証」という位置づけ。

## 予測される質問と答え（Q&A 対策）

**Q1. 「仕様に前提を自然言語で書けばいいのでは？」**
→ 方向は正しい。違いは**出所**：「何を書くか」の正しさ・網羅性を保証できる一次情報は証明の仮説だけ。人が散文で書き足すのは検査不能な第二の翻訳で、実際に48/57件が拾えていないという実測がある。

**Q2. 「48件はバグか？」**
→ 違う。バグの個数ではなく「仕様の文章に安全性要件として明示されていない」の判定結果。下流の監査への効果は別途検証（未評価）。

**Q3. 「Nimbus #461 は前提の非明示が原因か？」**
→ 因果は示していない。同じ処理領域（正当化履歴・確定判定）に監査の盲点があったという位置づけ。

**Q4. 「LLMが抽出を間違えるのでは？」**
→ 抽出段はLLMを使わない。定理文の型シグネチャから仮説を構文的に列挙する決定的処理（speca-lean4-plugin も fixture フォールバックを実物照合で検出した実績あり）。LLMは後段の「明示/非明示」判定だけ。

**Q5. 「仮想例（8人・2/3）は実際のEthereumか？」**
→ 説明用の模式例。実際のバリデータは数十万人規模で重みも不均等。「分母の定義が違いうる」ことを示す図。

**Q6. 「57件は独立した条件か？」**
→ 延べ件数。同一概念の反復をまとめると10概念、うち7概念が非明示で一致。

**Q7. 「Coq での形式化（Runtime Verification）との違いは？」**
→ 検証対象は同じ Gasper の核心定理。Coq には RV と Alturki の先行形式化があり、gasper-lean4 は Lean 4 初で、選択公理を排除した構成的証明という差分もある。抽出手法は証明系を選ばない。

**Q8. 「前提を全部 assert にすればいいのでは？」**
→ しない。前提には実装で保つ条件と、モデル・環境の仮定（攻撃者の規模等）が混ざる。条件の意味と確認責任を割り当てるのが提案。

**Q9. 「差分テストで実装間の違いは拾えるのでは？」**
→ 実装が**揃って間違える**（同じ誤解で一致する）場合に差分は出ない。SPECA 論文でも「correlated misinterpretations」として同じ問題が指摘されている。

**Q10. 「Lean を現場の人が読めないのでは？」**
→ 読まない設計。翻訳済みの前提一覧（日本語の確認項目 or JSON）を渡す。本研究は「証明の成果を現場へ渡す」研究であり、証明の書き方の話ではない。

**Q11. 「手順（2/3の計算）は合っているのに何が問題？」**
→ 算術ではなく**何の集合・どの状態を数えたか**がずれうる。Nimbus #461 も算術は正しく、確定判定に渡す状態が壊れていた。

**Q12. 「仕様書自体が間違っているという話か？」**
→ 違う。仕様の手順は正しいが、「その手順が成り立つ前提条件」が下流に届いていないという構造の問題。仕様の非難ではなく情報経路の補完の話。

**Q13. 「この研究はどこから出てきた？グラントとの関係は？」**
→ EF Security Grant FY26-2399「SPECA & LeanAgent」の成果群が出発点。証明→監査の経路（speca-lean4-plugin）は M2 で実装済み。本研究はその**一次情報供給元（証明の前提）が仕様文書で拾えているかを検証した予備調査**。

**Q14. 「57件と speca-lean4-plugin の 53仮説/61プロパティは違うの？」**
→ 別の数え物。plugin は gasper track の25定理から53仮説を61プロパティへ変換。本研究の57は17定理由来の確認項目対応の延べ件数。対象も単位も違う。

**Q15. 「この研究の新規性は？plugin がもうあるのでは？」**
→ plugin は「定理→監査プロパティ」の変換器。本研究は「仕様文書だけでは証明の前提を拾いきれない」ことを自動照合で測った点が新しい。plugin の供給元側の検証であり、両者は競合ではなく連携する。

**Q16. 「Beyond Code Reasoning は査読を通ったの？」**
→ NDSS'27 ではリジェクト。決定的理由は標準プロンプトLLMとのベースライン比較が無かった点で、計測結果自体は争われていない。arXiv preprint は公開済み。本研究の主張はその論文の結果に依存しない。

**Q17. 「なぜイーサリアム？」**
→ 仕様・複数実装・機械証明の3点が公開されている稀有な対象だから。手法自体は対象を選ばない（Appendix参照）。

**Q18. 「plugin の ethvuln track は本研究と関係ある？」**
→ 発想は近いが別物。ethvuln は「実バグが破った不変条件」を命題化した目録（証明なし・statement-level）。本研究は「証明済み定理の仮説」から出発する。証明由来である点が保証の強さの違い。
